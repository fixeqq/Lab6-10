1. เปรียบเทียบ FIFO กับ LRU

จากชุดข้อมูลในสคริปต์ FIFO เกิด Page Fault 9 ครั้ง ส่วน LRU เกิด 7 ครั้ง LRU จึงทำงานดีกว่า 2 ครั้ง เพราะมันดูว่าหน้าใดถูกใช้งานล่าสุดแล้วเก็บหน้านั้นไว้ เมื่อ RAM เต็ม LRU จะนำหน้าที่ไม่ได้ถูกใช้นานที่สุดออก

FIFO ดูเพียงลำดับที่หน้าเข้ามา จึงอาจนำหน้าที่กำลังจะถูกใช้อีกครั้งออกไป แม้หน้านั้นจะยังสำคัญกับโปรแกรมอยู่ ผลการทดลองจึงมี Page Fault มากกว่า

2. ความเข้าใจเรื่อง Thrashing

ฉันเข้าใจว่า Thrashing คือภาวะที่ระบบเสียเวลาไปกับการย้ายข้อมูลระหว่าง RAM กับ Disk มากกว่าการประมวลผลจริง ในการทดลอง แบบที่ข้อมูลอยู่ใน RAM ทำงานเร็วกว่า เพราะเข้าถึงข้อมูลได้ทันที ส่วนแบบ Swap ต้องเปิด อ่าน และเขียนไฟล์ซ้ำหลายรอบ จึงใช้เวลามากกว่า

เวลาที่วัดได้ขึ้นอยู่กับเครื่องและพื้นที่เก็บข้อมูล ดังนั้นต้องใช้ค่าที่รันได้จริงใน Codespace แทนค่าตัวอย่าง

3. การลด batch_size ช่วยอย่างไร

การลด batch_size ทำให้ข้อมูลและค่าชั่วคราวที่ต้องเก็บในแต่ละรอบมีขนาดเล็กลง หน่วยความจำจึงมีโอกาสพอสำหรับโมเดลและข้อมูลที่กำลังใช้งานอยู่มากขึ้น เมื่อไม่ต้องย้ายหน้าออกไปที่ Disk บ่อย ๆ ปัญหา Thrashing ก็ลดลง แม้แต่ละรอบจะประมวลผลข้อมูลได้น้อยลงก็ตาม

4. สรุปและการประยุกต์ใช้

Virtual Memory ช่วยให้โปรแกรมทำงานต่อได้เมื่อ RAM ไม่พอ โดยย้ายบางหน้าไปไว้บน Disk แต่ Disk ช้ากว่า RAM มาก จึงเป็นเพียงทางแก้เรื่องพื้นที่ ไม่ใช่ทางแก้เรื่องความเร็ว

สำหรับงาน AI ฉันจะเริ่มจากลด batch_size ตรวจสอบการใช้ RAM/VRAM และอาจใช้ Gradient Accumulation หรือ Gradient Checkpointing แทนการปล่อยให้ระบบ Swap ตลอดเวลา เพราะ Thrashing ทำให้เวลาฝึกโมเดลเพิ่มขึ้นมาก
