1. Inodes และ Metadata

ถ้าใช้คำสั่ง mv เปลี่ยนชื่อไฟล์ภายใน File System เดียวกัน Inode Number จะไม่เปลี่ยน เพราะการ Rename เปลี่ยนชื่อที่ชี้ไปยังไฟล์ แต่ไม่ได้สร้างข้อมูลไฟล์ใหม่ ส่วนรายละเอียดอย่างขนาด เวลา และสิทธิ์จะยังอยู่กับ Inode เดิม

2. POSIX Permissions

ค่าที่ใช้คือ 750 เพราะ Owner ได้ Read/Write/Execute เท่ากับ 7, Group ได้ Read/Execute เท่ากับ 5 และ Others ไม่มีสิทธิ์เท่ากับ 0

3. การป้องกัน Model Weights

OS-level permission ป้องกันตั้งแต่ตอนโปรเซสขอเปิดไฟล์ ไม่ได้ขึ้นอยู่กับว่าโปรแกรมเขียน try-except ไว้ดีแค่ไหน หากใช้ os.chmod(0o444) ไฟล์จะอ่านได้แต่เขียนไม่ได้ตามสิทธิ์ที่ Kernel บังคับใช้ โปรแกรมที่เปิดไฟล์ในโหมดเขียนจึงถูกปฏิเสธก่อนแก้ข้อมูลจริง

4. สรุปและการประยุกต์ใช้

Inode เก็บ Metadata ของไฟล์ เช่น เจ้าของ ขนาด และตำแหน่งข้อมูล ส่วน Permission แบ่งสิทธิ์เป็น Owner, Group และ Others สำหรับ Model Weights ฉันจะตั้งไฟล์เป็น Read-only ด้วย os.chmod และกำหนดเจ้าของหรือกลุ่มด้วย chown เมื่อมีสิทธิ์เพียงพอ วิธีนี้ช่วยกันโปรเซสที่ไม่ควรแก้ไขไฟล์ได้ดีกว่าการตรวจสอบในโค้ดเพียงอย่างเดียว
