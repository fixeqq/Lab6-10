1. บทบาทของระบบปฏิบัติการ

File System Security

ใน _execute_job ระบบตรวจด้วย os.path.exists(dataset_path) ก่อนเริ่มงาน Workload D ขอใช้ไฟล์ secret_keys.txt ซึ่งไม่มีอยู่ จึงถูกปฏิเสธและไม่ถูกจัดสรรทรัพยากร

Memory Management

โค้ดใช้ while loop ตรวจ available_ram_gb และจะหัก RAM ออกเมื่อมีพอเท่านั้น ถ้า RAM ยังไม่พอ งานจะรอแทนการฝืนรัน วิธีนี้ช่วยไม่ให้หลายงานใช้ RAM เกินจริงจนเกิด Thrashing

Deadlock Avoidance

ก่อนล็อก GPU โค้ดเรียงหมายเลขด้วย sorted(req_gpus) ทุกงานจึงขอทรัพยากรตามลำดับเดียวกัน ลดโอกาสเกิด Circular Wait ที่ทำให้แต่ละงานรอกันเอง

CPU Scheduling Queue

งานทุกงานถูกส่งเข้า job_queue แล้ว Scheduler ดึงไปสร้าง Worker สำหรับจัดการทรัพยากร งานจึงไม่ต้องทำงานทั้งหมดในโปรเซสเดียวและสามารถใช้ทรัพยากรที่ไม่ชนกันพร้อมกันได้

2. Hardware Utilization

Workload A ใช้ GPU 0, 1, 2 เหลือ GPU 3 ไว้ให้ Workload C ส่วน Workload B ไม่ใช้ GPU จึงทำงานบน CPU ควบคู่กับ A ได้ แต่ละงานใช้ RAM ตามจำนวนที่ขอและมี Lock ควบคุม GPU ทำให้ระบบไม่จัดสรรทรัพยากรเกินจำนวนที่มี งานจึงไม่บล็อกกันทั้งหมด

3. บทสรุปรายวิชา

ความรู้เรื่อง OS ทำให้ฉันมองเห็นข้อจำกัดที่เกิดขึ้นตอนระบบรันจริง ไม่ใช่แค่เขียนโมเดลให้ทำงานได้ เช่น รู้ว่างานจะติดที่ RAM, คิว CPU, Disk หรือสิทธิ์ไฟล์ตรงไหน ความเข้าใจนี้ช่วยให้ออกแบบระบบ AI และ MLOps ที่ใช้ทรัพยากรคุ้มค่า แก้ปัญหาได้เร็ว และไม่ทำให้โมเดลหรือข้อมูลสำคัญเสียหาย

4. สรุปภาพรวมของ Capstone

การจัดสรร Memory ทำให้งานไม่ใช้ RAM เกิน File System Security กรองไฟล์ที่เข้าถึงไม่ได้ การเรียงลำดับการขอ GPU ช่วยลด Deadlock และ Job Queue ช่วยจัดลำดับงาน ทั้งสี่ส่วนทำให้ Training, Preprocessing และ Inference ทำงานพร้อมกันได้โดยไม่แย่งทรัพยากรกันจนระบบล้ม
