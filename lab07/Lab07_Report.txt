1. Convoy Effect

ใน FCFS P1 ใช้ CPU นาน 10 หน่วยเวลา จึงทำให้ P2 ต้องรอจนถึงเวลา 10 และ P3 ต้องรอจนถึงเวลา 12 แม้ทั้งสองงานจะสั้นมากก็ตาม อาการที่งานสั้นหลายงานต้องต่อแถวยาวหลังงานใหญ่แบบนี้คือ Convoy Effect

2. การเลือก Time Quantum

ถ้า Time Quantum ใหญ่มาก เช่น 100 งานแรกจะได้ใช้ CPU จนเกือบจบก่อนส่งต่อ งานจึงมีพฤติกรรมใกล้เคียง FCFS

ถ้า Time Quantum เล็กมาก เช่น 0.0001 ระบบจะสลับงานถี่เกินไป เวลาและ CPU ที่ใช้ในการ Context Switch จะมีสัดส่วนสูง ทำให้เวลาส่วนหนึ่งไม่ได้ใช้ประมวลผลงานจริง

3. การประยุกต์กับ AI Inference

ในแบบ Round Robin เซิร์ฟเวอร์ให้แต่ละคำขอสร้าง Token ทีละช่วงสั้น ๆ แล้วนำงานที่ยังไม่เสร็จกลับเข้าคิว ดังนั้นคำขอสั้นของ User B ไม่ต้องรอให้บทความของ User A สร้างครบทั้งหมด User B จึงได้รับ Token แรกเร็วขึ้นและรู้สึกว่าระบบตอบสนองดีขึ้น ค่า TTFT ก็ลดลง

4. สรุปและการประยุกต์ใช้

FCFS เข้าใจง่าย แต่ถ้างานแรกใหญ่ งานเล็กที่มาทีหลังจะรอนาน Round Robin แบ่งเวลาให้ทุกงานเป็นช่วง ๆ จึงเหมาะกับ AI Inference API ที่มีผู้ใช้พร้อมกันจำนวนมากกว่า เพราะลดการถูกงานยาวงานเดียวขวางคิวทั้งหมด
